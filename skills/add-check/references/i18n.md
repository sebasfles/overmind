# Example: i18n check for a Next.js app using next-intl

```markdown
---
name: i18n
model: sonnet
paths:
  - apps/web/src/**/*.tsx
  - apps/web/messages/**/*.json
reference: docs/conventions/i18n.md
---

# i18n

Every user-facing string in the changed files goes through `useTranslations` or `getTranslations`; none is a literal in JSX text, `aria-label`, `placeholder`, `title` or `alt`.
Every key used in the diff exists in `messages/en.json`.
Every locale file under `messages/` has the same key set as `en.json` after the change.
Keys follow the namespace convention of the reference: `{{page}}.{{section}}.{{element}}`.
Dates, numbers and currencies use the formatters the reference names, never `toLocaleString` or manual formatting.
Report as clean: log messages, test fixtures, developer-only error messages, and strings inside `data-testid`.
```

Why it works: each line names the exact API the project uses, so the checker matches code, not intent; the last line is what keeps false positives down.
